# Migrating from 0.1 to 0.2

Version 0.2 is a scientific and performance release, not a drop-in numerical patch.
Review stored scores and partitions before replacing results generated by 0.1.

## Julia compatibility

The supported floor is Julia 1.10. Julia 1.13 is the primary development runtime and
CI also tests 1.12. Users on Julia 1.6--1.9 must upgrade Julia or remain on
CorePeriphery.jl 0.1.

## 0.2.0 default changes

These defaults changed during the 0.2.0 review. Each one alters results of code that
relies on the previous behaviour, so check stored outputs against the new rule:

- **Strict median partition.** Continuous detectors (`borgatti_everett_continuous`,
  `random_walker_profiling`, `minres_symmetric`, `minres_svd`, `minres_svd_directed`,
  `rombach_core_score`) put only nodes *strictly above* the median coreness in
  `core_nodes`; nodes tied at the median are periphery (a star's leaves no longer join
  the hub, and a profile with many zero persistences no longer makes every node core).
  Choose the rule explicitly with `partition=:none|:threshold|:core_size`.
- **Rombach.** `beta` is the periphery fraction of Rombach et al. (2017) eq. (4.9),
  implemented with the paper's `⌊βN⌋` boundary instead of the former `i/n` ranks;
  `coreness` is normalised to sum to one (it used to be the raw `[0, 1]` template);
  `quality` is the full double sum of eq. (4.10) (twice the former upper-triangular
  value on the same vector); and the default `partition=:beta` reports the
  `N − ⌊βN⌋` core ranks as `core_nodes` instead of a median split. The new
  `rombach_core_score` provides the paper's aggregate core score (eq. 4.11).
- **Kojaku--Masuda configuration null.** The `:configuration` objective of
  `multiple_cp_pairs` now includes the `i = j` null term of Kojaku & Masuda (2018)
  eq. (13), which the earlier implementation omitted; configuration-null qualities
  are lower by `Σ_{i ∈ core} d_i² / (4m²)` and fitted partitions can differ.
- **Penalised pair selection.** `multiple_cp_pairs` defaults to
  `pair_selection=:penalized`; pass `pair_selection=:objective` for the former
  raw-objective rule, which over-partitions a single planted pair.
- **Significance defaults.** `cp_significance` draws `n_samples=999` (was 199) and
  forwards a child RNG to detectors with an `rng` keyword (`pass_rng=true`, was
  `false`). The result gains `null_mean`, `null_std`, and `zscore`; use `isequal` to
  compare results whose z-score may be `NaN`.
- **Conflicting duplicate edges.** `adjacency_to_matrix` raises an `ArgumentError`
  when a dyad occurs with conflicting weights; the previous last-weight-wins behaviour
  is available as `combine=:last` (also `:sum`, `:max`, `:min`), and `directed=true`
  keeps `(i, j)` and `(j, i)` distinct instead of symmetrising.
- **Isolates and components.** Isolates receive coreness `0` and are never core
  (`multiple_cp_pairs` gives them pair label `0`); an edgeless network returns an
  empty core; detectors warn once per session on input with more than one non-trivial
  connected component.
- **Deprecations.** Rossa `n_walks`/`walk_length` and Lip `max_iter` emit
  `Base.depwarn`; `rossa_profile_ensemble` raises an error when `tie_break` or `rng`
  is passed through its forwarded keywords instead of silently overriding.
- **Errors.** Non-convergence (ARPACK, Rossa stationary solvers, incomplete
  configuration switching) raises the new `ConvergenceError` instead of
  `ArgumentError`/`ErrorException`; `Symmetric`/`Transpose` wrappers around sparse
  matrices are unwrapped so they take the sparse kernels.

## Algorithm output changes

Lip, LowRank-Core, Rombach, Rossa, Surprise, multi-pair detection, and several shared
quality calculations now implement different or corrected published quantities. Do not
expect historical scores to remain numerically identical. The ablation report separates
semantic changes from storage-specific optimization.

Raw quality values remain algorithm-specific. Replace code that selects an algorithm by
`maximum(result.quality)` with a common external validation measure or a matched
objective.

## Rossa

Calls without new keywords retain deterministic node-index tie resolution:

```julia
result = random_walker_profiling(A)
```

Use the paper's stochastic hierarchy explicitly:

```julia
using Random
result = random_walker_profiling(
    A; tie_break=:paper, rng=MersenneTwister(42),
)
```

Asymmetric input is now accepted when strongly connected. The default directed solver
remains sparse-friendly lazy iteration; `stationary_method=:linear` is available for a
robust dense solve. `n_walks` and `walk_length` are ignored compatibility keywords and
should be removed from new code.

## MINRES

`minres_svd` remains a `CPResult` compatibility projection of the directed `u*v'`
model. Prefer explicit names in new code:

- `minres_svd_directed` for separate sender and receiver factors;
- `minres_symmetric` for the symmetric `w*w'` model.

## Multiple pairs

The pair count is now chosen by the BIC-inspired structural penalty by default; the
0.1-style raw-objective rule remains available:

```julia
result = multiple_cp_pairs(A; pair_selection=:objective)
```

Inspect `candidate_pair_counts`, `candidate_qualities`, and `selection_scores` rather
than treating `n_pairs` as uncertainty-free. Kojaku & Masuda (2018) recommend the
configuration null (`multiple_cp_pairs_config`, or `null_model=:configuration`),
which is now their eq. (13) exactly; `:er` stays the default for continuity with the
2017 paper.

## Borgatti-Everett family

`borgatti_everett_discrete` and `label_switching_cp` accept `cp_block=:missing` (the
missing-block model of BE 2000 eq. 4), `directed=true`, and (discrete only) `n_runs`,
`rng`, and `method=:exhaustive`; `borgatti_everett_continuous` accepts `directed=true`.
Defaults are unchanged (`cp_block=:ones`, undirected, one greedy start), so existing
calls return the same fits apart from the strict median split and the isolate rule.

## Significance testing

Degree-preserving switching must now complete all requested swaps. Networks with no
valid simple switch raise a `ConvergenceError` instead of silently returning an
ineffective null. Use a larger `max_swap_attempts`, select a different null model, or
explicitly accept the limitation:

```julia
result = cp_significance(
    A, detector; swap_shortfall=:accept,
)
@assert !result.null_diagnostics.complete
```

New `:directed_configuration` and `:weight_permutation` nulls support directed binary
and weighted workflows. Their preserved constraints are recorded in
`null_diagnostics`. The binary nulls reject weighted input with an error that points to
`:weight_permutation`. Sparse input is now sampled in sparse form; dense and sparse
inputs give identical results for the same `rng`.

## Graphs.jl and sparse input

Graphs.jl is now a weak dependency. Loading both packages activates direct detector
methods for graph objects. Sparse matrices preserve estimator definitions, but small
graphs may remain faster as dense matrices.

## Result structures

Code using named fields remains the recommended pattern. Positional construction or
destructuring of `CPMultiResult` and `CPSignificanceResult` must account for their new
diagnostic and effect-size fields. All result types now define `==`, `isequal`, and
`hash`, so they can be deduplicated and used as dictionary keys; `null_diagnostics` is
the concrete `CorePeriphery.NullDiagnostics` type.

See the algorithm contract page, development record, and changelog for the complete
behavioral inventory.
