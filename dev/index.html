CorePeriphery.jl

A Julia package for detecting core-periphery structure in networks.

Overview

Core-periphery structure is a fundamental mesoscale pattern in complex networks where nodes are partitioned into two groups:

  • Core: A densely interconnected group of central nodes
  • Periphery: Sparsely connected nodes that attach to the core but not to each other

This pattern appears in many real-world networks including social networks, economic systems, biological networks, and transportation infrastructure. CorePeriphery.jl provides multiple algorithms for detecting and quantifying this structure.

Features

  • Published discrete, continuous, spectral, directed, and multi-pair methods, including the Borgatti-Everett missing-block model, an exact discrete optimum for small sociograms, and Rombach's aggregate core score
  • Weighted network support for analyzing networks with edge weights
  • Directed in/out coreness via CPDirectedResult, and directed=true in the Borgatti-Everett family
  • Labelled edge lists (adjacency_to_matrix(edges) returns the matrix and node labels) and block_densities for reporting a fit
  • Optional Graphs.jl integration and sparse-matrix input
  • Monte Carlo significance tests with undirected, directed, and weighted nulls, effect sizes (zscore), sparse-aware sampling, and explicit swap-completion diagnostics
  • Matrix-free sparse kernels for spectral, directed, and greedy methods
  • Consistent API with unified result structures across all algorithms, explicit partition rules for continuous scores, and an isolate guarantee (isolates are never core)

Installation

CorePeriphery.jl is not yet in the General registry. Install it from GitHub:

using Pkg
Pkg.add(url="https://github.com/simoneSantoni/CorePeriphery.jl")

Or for development:

using Pkg
Pkg.develop(path="/path/to/CorePeriphery.jl")

Quick Start

julia> using CorePeriphery

julia> edges = [
           (1, 2), (1, 3), (1, 4), (1, 5),  # Node 1 connected to many
           (2, 3), (2, 4), (2, 5),           # Node 2 also well-connected
           (3, 4), (3, 5),
           (6, 1), (7, 2)                    # Peripheral nodes
       ];

julia> A = adjacency_to_matrix(edges, 7);

julia> result = borgatti_everett_continuous(A)
CPResult: Borgatti-Everett Continuous
  nodes = 7, core = 3, periphery = 4
  quality = 0.7818

julia> println("Coreness scores: ", result.coreness)
Coreness scores: [0.7, 0.7, 0.65, 0.5, 0.5, 0.2, 0.2]

julia> println("Core nodes: ", result.core_nodes)
Core nodes: [1, 2, 3]

julia> println("Periphery nodes: ", result.periphery_nodes)
Periphery nodes: [4, 5, 6, 7]

julia> println("Quality: ", result.quality)
Quality: 0.78178482001133

julia> block_densities(A, result)   # report the block densities with the fit
(core_core = 1.0, core_periphery = 0.6666666666666666, periphery_core = 0.6666666666666666, periphery_periphery = 0.0)

Node identifiers need not be integers: A, labels = adjacency_to_matrix(edges) accepts any identifiers and returns the label of every row, so labels[result.core_nodes] reports the core in the original names (see the Tutorial).

Choosing an Algorithm

Use CaseRecommended Algorithm
Fast binary classificationlip_discrete or label_switching_cp
Exact discrete optimum on a small sociogramborgatti_everett_discrete with method=:exhaustive
Continuous coreness scoresborgatti_everett_continuous or rombach_continuous
Parameter-averaged Rombach core scorerombach_core_score
Published spectral partitionspectral_method
Directed networksrandom_walker_profiling, minres_svd_directed, or the Borgatti-Everett family with directed=true
Symmetric MINRESminres_symmetric
Multiple CP structuresmultiple_cp_pairs
Tunable core sizerombach_continuous (beta is the periphery fraction)
Statistical significance and effect sizescp_significance
Configuration null conveniencemultiple_cp_pairs_config
Block-density reportingblock_densities

Raw quality values are algorithm-specific; do not use them to rank algorithms against each other.

Performance snapshots

CorePeriphery.jl compared with cpnet

Across three identical planted fixtures and all nine comparable algorithm configurations, CorePeriphery.jl was faster in 25 of 27 warmed fits. The table reports the median cpnet/Julia runtime ratio across the three fixtures; a value above 1 means that the Julia call completed sooner. Fit budgets are not matched: cpnet runs five stochastic starts for BE, MINRES, and Surprise where the Julia call is a single deterministic fit, so the largest ratios compare configured estimators rather than equal optimizer work.

These are configured-estimator timings on small n = 20, 40, 48 fixtures, not equal-work or large-network speedups. Several cpnet configurations use more stochastic starts than their deterministic Julia counterparts. See Performance for every timing pair, fit budgets, fixture densities, methodology, and interpretation limits.

Julia dense and sparse scaling

CorePeriphery.jl provides matrix-free sparse paths for its principal spectral, directed, and greedy algorithms. On the package's synthetic n = 512 scaling fixture, the following warmed median runtimes were measured with Julia 1.12, one BLAS thread, and seven repetitions:

AlgorithmDenseSparseSparse speedup
lip_discrete0.906 ms0.132 ms6.8×
minres_symmetric (max_iter = 50)1.565 ms0.337 ms4.6×
spectral_method39.754 ms4.215 ms9.4×
random_walker_profiling18.480 ms0.832 ms22.2×
minres_svd_directed (max_iter = 50)7.096 ms0.675 ms10.5×

Absolute timings are host-specific. The scaling results show the effect of sparse storage on the benchmark fixture and are not intended to predict runtime for every network.
