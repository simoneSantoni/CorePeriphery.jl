Module

CorePeriphery — Module
CorePeriphery

A Julia module implementing various core-periphery detection algorithms for network analysis.

Core-periphery structure is a mesoscale pattern in networks where nodes are divided into a densely interconnected core and a sparsely connected periphery.

Algorithms Implemented

  • Borgatti-Everett continuous model (2000)
  • Borgatti-Everett discrete model (2000)
  • Lip's fast discrete algorithm (2011)
  • Rombach's generalized model (2017)
  • Spectral method (Cucuringu et al., 2016)
  • Random walker profiling (Rossa et al., 2013)
  • MINRES/SVD for asymmetric networks (Boyd et al., 2010)
  • Multiple core-periphery pairs (Kojaku & Masuda, 2017)
  • Surprise-based detection (Jeude et al., 2019)
  • Label-switching algorithm (Yanchenko & Sengupta, 2025)

References

  • Borgatti, S.P., Everett, M.G. (2000). Models of core/periphery structures.
  • Lip, S.Z.W. (2011). A Fast Algorithm for the Discrete Core/Periphery Bipartitioning Problem.
  • Rombach, M.P., et al. (2017). Core-Periphery Structure in Networks (Revisited).
  • Cucuringu, M., et al. (2016). Detection of core-periphery structure using spectral methods.
  • Rossa, F.D., et al. (2013). Profiling core-periphery network structure by random walkers.
  • Boyd, J.P., et al. (2010). Computing core/periphery structures and permutation tests.
  • Kojaku, S., Masuda, N. (2017). Finding multiple core-periphery pairs in networks.
  • Jeude, J., et al. (2019). Detecting Core-Periphery Structures by Surprise.
  • Yanchenko, K., Sengupta, S. (2025). A fast label-switching algorithm for core-periphery detection.

Result Types

CorePeriphery.CPResult — Type
CPResult

Result structure for core-periphery detection algorithms.

Fields

  • coreness::Vector{Float64}: Coreness score for each node (higher = more core-like). Isolates (nodes with zero strength) always score 0.
  • core_nodes::Vector{Int}: Indices of nodes classified as core. For the continuous detectors this is the split produced by their partition keyword (a median rule by default), not an estimate of the model; isolates are never core.
  • periphery_nodes::Vector{Int}: Indices of nodes classified as periphery
  • quality::Float64: Quality score of the partition (algorithm-specific)
  • algorithm::String: Name of the algorithm used

CorePeriphery.CPSignificanceResult — Type
CPSignificanceResult

Monte Carlo significance result for a detected core-periphery structure. pvalue uses the conservative plus-one estimator (1 + count(null_quality >= observed_quality)) / (n_samples + 1). null_diagnostics is a NullDiagnostics recording the preserved constraint and switching completion.

Fields

  • observed_quality::Float64: detector quality on the observed network
  • null_qualities::Vector{Float64}: detector quality on every null sample
  • pvalue::Float64: plus-one Monte Carlo p-value
  • significant::Bool: pvalue <= alpha
  • alpha::Float64: significance level used for significant
  • null_model::Symbol: null model that generated the samples
  • null_diagnostics::NullDiagnostics: sampler diagnostics
  • null_mean::Float64: mean of null_qualities
  • null_std::Float64: sample standard deviation of null_qualities (NaN with a single sample)
  • zscore::Float64: (observed_quality - null_mean) / null_std, an effect size in null standard deviations; NaN when null_std is zero or undefined

ConvergenceError(msg)

Exception raised when an iterative or numerical procedure fails to reach the requested accuracy: an ARPACK eigensolve that does not converge, a stationary distribution solver that exhausts its iteration budget, or a configuration-null edge-switching chain that cannot complete the requested number of swaps under the swap_shortfall=:error policy. CorePeriphery.borgatti_everett_continuous — Function
borgatti_everett_continuous(A; max_iter=1000, tol=1e-6, step=0.05, init=nothing,
                            directed=false, partition=:median,
                            threshold=nothing, core_size=nothing)

Borgatti-Everett continuous core-periphery model.

Finds coreness vector c that maximizes correlation with ideal pattern Δ[i,j] = c[i]*c[j].

Arguments

  • A: Adjacency matrix (n x n)
  • max_iter: Maximum iterations
  • tol: Convergence tolerance
  • step: Coordinate-search resolution in (0, 1]
  • init: Initial coreness vector (optional)
  • directed: With false (default) A must be symmetric and the correlation runs over the strict upper triangle. With true, asymmetric input is accepted and the correlation runs over all off-diagonal ordered dyads, as UCINET does for directed sociometric data; symmetric input gives the same fit either way.
  • partition: Core/periphery split rule applied to the coreness vector: :median (default; nodes strictly above the median are core), :none (all nodes periphery), :threshold (nodes strictly above threshold), or :core_size (the core_size highest-coreness nodes, ties broken by lower index)
  • threshold: Cutoff used by partition=:threshold
  • core_size: Number of core nodes used by partition=:core_size

Isolates (nodes with zero strength) always receive coreness 0 and are never in core_nodes. A warning is emitted (once per session) when A has more than one connected component with at least two nodes.

Returns

  • CPResult with continuous coreness scores

Reference

Borgatti, S.P., Everett, M.G. (2000). Models of core/periphery structures.

CorePeriphery.rombach_continuous — Function
rombach_continuous(A; alpha=0.5, beta=0.5, max_iter=1000, tol=1e-6,
                   n_runs=10, rng=Random.default_rng(),
                   partition=:beta, threshold=nothing, core_size=nothing)

Rombach's generalized continuous core-periphery model at a single point (alpha, beta) of the parameter plane (Rombach et al. 2017, §4.2).

The core vector C is a shuffle of the transition-function template C*(α, β) of eq. (4.9), normalised so that its entries sum to 1 as in the paper, chosen to maximise the core quality of eq. (4.10), R_{α,β} = Σ_{i,j} A[i,j] C[i] C[j] (the full double sum, so each undirected edge counts twice). The search uses greedy pair swaps and random restarts. quality is R_{α,β} of the returned vector, not a Pearson correlation; coreness is C (its entries sum to 1; multiply by sum(C*) to recover the raw template values, which lie in [0, 1]). For the parameter-averaged aggregate core score of eq. (4.11) see rombach_core_score.

Arguments

  • A: Adjacency matrix (symmetric)
  • alpha ∈ [0, 1]: Sharpness of the core-periphery boundary, i.e. the size of the score jump between the highest-scoring peripheral node and the lowest-scoring core node (alpha = 1 is a discrete classification)
  • beta ∈ [0, 1]: Fraction of nodes in the periphery: the first ⌊βN⌋ template ranks are peripheral and the remaining N - ⌊βN⌋ are core, so the core shrinks from N nodes at beta = 0 to none at beta = 1
  • max_iter: Maximum swap iterations per run
  • tol: Minimum objective gain for a swap to be accepted
  • n_runs: Number of random restarts
  • rng: Random-number generator used for restart permutations
  • partition: Core/periphery split rule applied to the coreness vector: :beta (default; the N - ⌊βN⌋ nodes holding the core ranks of the template, i.e. the core implied by beta), :median (nodes strictly above the median are core), :none (all nodes periphery), :threshold (nodes strictly above threshold), or :core_size (the core_size highest-coreness nodes, ties broken by lower index)
  • threshold: Cutoff used by partition=:threshold
  • core_size: Number of core nodes used by partition=:core_size

Isolates (nodes with zero strength) are removed before fitting: the template is built for the N' non-isolated nodes, isolates receive coreness 0, and they are never in core_nodes. A warning is emitted (once per session) when A has more than one connected component with at least two nodes.

Returns

  • CPResult with continuous coreness scores

Reference

Rombach, M.P., et al. (2017). Core-Periphery Structure in Networks (Revisited).

CorePeriphery.rombach_core_score — Function
rombach_core_score(A; alphas=0.1:0.1:1.0, betas=0.1:0.1:1.0, max_iter=1000,
                   tol=1e-6, n_runs=3, rng=Random.default_rng(),
                   partition=:median, threshold=nothing, core_size=nothing)

Aggregate core score of Rombach et al. (2017) eq. (4.11),

CS(i) = Z Σ_γ C_i(γ) R_γ,    γ = (α, β) ∈ alphas × betas,

where C(γ) is the optimal normalised shuffle of the eq. (4.9) template found by rombach_continuous at γ, R_γ is its core quality (eq. 4.10), and Z is chosen so that max_k CS(k) = 1. This is the paper's recommended deliverable: a continuous centrality-like coreness that averages over the parameter plane instead of fixing one (α, β). The paper averages over the grid α, β ∈ 0.01:0.01:1 (10,000 points); the default 10 × 10 grid keeps the cost at 100 optimisations and can be refined through alphas/betas.

Arguments

  • A: Adjacency matrix (symmetric)
  • alphas, betas: Grid values in [0, 1] (see rombach_continuous for their meaning; beta is the periphery fraction)
  • max_iter, tol, n_runs, rng: Optimiser settings passed to each (α, β) fit, in grid order (alphas outer, betas inner) so results are reproducible for a seeded rng
  • partition, threshold, core_size: Split rule applied to the aggregate score, as in borgatti_everett_continuous; default :median

Isolates receive score 0 and are never in core_nodes. The result's quality is the mean core quality R_γ over the grid; algorithm is "Rombach aggregate core score".

Reference

Rombach, M.P., et al. (2017). Core-Periphery Structure in Networks (Revisited).

random_walker_profiling(A; tie_break=:deterministic,

                        stationary_distribution=nothing,
                        stationary_tol=1e-12,
                        stationary_max_iter=100_000,

Compute the Della Rossa persistence profile of an undirected connected or directed strongly connected network. The default deterministic mode replaces the paper's random choices with lower node index; tie_break=:paper restores the published stochastic selection rule using rng. The result quality is the paper's cp-centralization. Directed inputs accept stationary_method=:lazy, :linear, or :auto, or a validated stationary_distribution supplied by the caller; a stationary solver that does not converge raises ConvergenceError.

Keyword arguments

  • tie_break: :deterministic (default) or the stochastic, paper-exact :paper
  • rng: Random-number generator used when tie_break=:paper
  • stationary_method: Directed solver, :lazy (default), :linear, or :auto
  • stationary_distribution: Optional validated stationary probability vector
  • stationary_tol: L1 convergence tolerance for the directed stationary distribution
  • stationary_max_iter: Maximum stationary iterations for directed inputs
  • partition: Core/periphery split rule applied to the coreness vector: :median (default; nodes strictly above the median are core), :none (all nodes periphery), :threshold (nodes strictly above threshold), or :core_size (the core_size highest-coreness nodes, ties broken by lower index)
  • threshold: Cutoff used by partition=:threshold
  • core_size: Number of core nodes used by partition=:core_size
  • n_walks, walk_length: Deprecated legacy simulation keywords. They are accepted and ignored (profiling is analytic); passing them emits a deprecation warning (shown with --depwarn=yes).

rossa_stationary_distribution(A; method=:auto, tol=1e-12,

Compute the stationary distribution used by directed Della Rossa profiling. The returned StationaryDistributionResult includes the L1 balance residual, iteration count, and selected method. :linear is a robust dense constrained solve; :lazy uses stored-edge matrix-vector products and is suitable for large sparse graphs; :auto selects between them. CorePeriphery.rossa_profile_ensemble — Function
rossa_profile_ensemble(A; n_runs=100, rng=Random.default_rng(),

CorePeriphery.minres_symmetric — Function
minres_symmetric(A; max_iter=10_000, tol=1e-8, damping=0.5,
                 partition=:median, threshold=nothing, core_size=nothing)

Fit the symmetric off-diagonal rank-one MINRES model A[i,j] ≈ w[i]w[j]. Simultaneous damped fixed-point updates make the estimator equivariant under node permutation and independent of row/column orientation. The returned coreness is w normalized to [0,1]; quality is the fraction of squared off-diagonal adjacency weight explained by the fitted model.

This is a distinct estimand from minres_svd_directed, which fits separate sender and receiver factors.

Keyword arguments

  • max_iter, tol, damping: Fixed-point iteration budget, convergence tolerance, and damping weight in (0, 1]
  • partition: Core/periphery split rule applied to the coreness vector: :median (default; nodes strictly above the median are core), :none (all nodes periphery), :threshold (nodes strictly above threshold), or :core_size (the core_size highest-coreness nodes, ties broken by lower index)
  • threshold: Cutoff used by partition=:threshold
  • core_size: Number of core nodes used by partition=:core_size

CorePeriphery.minres_svd_directed — Function
minres_svd_directed(A; max_iter=1000, tol=1e-6,
                    partition=:median, threshold=nothing, core_size=nothing)

Fit the directed rank-one model A[i,j] ≈ u[i]v[j] over off-diagonal dyads by paired alternating least-squares searches. Matrix-vector products and work vectors are reused across iterations, including for sparse matrices. The returned out- and in-coreness scores are independently normalized to [0, 1]; residual is the unscaled least-squares residual and quality is the fraction of squared adjacency weight explained by the fit.

The two possible update orders are transpose-dual and their balanced factors are averaged, making the fit equivariant under transposition (which swaps out- and in-coreness) and under applying the same node permutation to rows and columns.

Keyword arguments

  • max_iter, tol: Alternating least-squares iteration budget and tolerance
  • partition: Core/periphery split rule applied to the coreness vector: :median (default; nodes strictly above the median are core), :none (all nodes periphery), :threshold (nodes strictly above threshold), or :core_size (the core_size highest-coreness nodes, ties broken by lower index)
  • threshold: Cutoff used by partition=:threshold
  • core_size: Number of core nodes used by partition=:core_size

Discrete Methods

CorePeriphery.borgatti_everett_discrete — Function
borgatti_everett_discrete(A; max_iter=1000, init=nothing, directed=false,
                          cp_block=:ones, n_runs=1, rng=Random.default_rng(),
                          method=:greedy)

Borgatti-Everett discrete core-periphery model.

Finds a binary partition maximizing the Pearson correlation between A and the ideal discrete pattern by greedy single-node flipping.

Arguments

  • A: Adjacency matrix
  • max_iter: Maximum sweeps per start
  • init: Initial binary assignment (optional; used by the first start)
  • directed: With false (default) A must be symmetric and the correlation runs over the strict upper triangle. With true, asymmetric input is accepted and the correlation runs over all off-diagonal ordered dyads (UCINET's convention for directed data); symmetric input gives the same fit either way.
  • cp_block: Ideal pattern for the core-periphery blocks. :ones (default) is Borgatti-Everett eq. (2), Δ[i,j] = max(c[i], c[j]), in which core-periphery ties are expected. :missing is their eq. (4), the model they recommend and UCINET's categorical default: core-periphery dyads are treated as missing data, so only the core-core and periphery-periphery blocks are correlated. See ideal_cp_matrix.
  • n_runs: Number of greedy starts. The first start is degree-based (or init); the others draw a random core of random size from rng. The best final correlation is returned. With n_runs=1 the fit is deterministic.
  • rng: Random-number generator for the restarts
  • method: :greedy (default) is the single-node flipping heuristic above. :exhaustive enumerates every core set of size 1:n-1 (Gray-code order, O(2^n · n) time) and returns a global optimum of the correlation, the first one met in enumeration order among ties; it is available for n ≤ 24 and ignores n_runs, rng, init, and max_iter. Greedy flipping, even with restarts, misses the optimum on a few percent of small graphs because the correlation surface has many local optima, so prefer :exhaustive for small sociograms.

Isolates (nodes with zero strength) always receive coreness 0 and are never in core_nodes. A warning is emitted (once per session) when A has more than one connected component with at least two nodes.

Returns

  • CPResult with binary coreness (0 or 1); quality is the correlation under the requested cp_block and dyad set

Reference

Borgatti, S.P., Everett, M.G. (2000). Models of core/periphery structures.

CorePeriphery.lip_discrete — Function
lip_discrete(A; max_iter=1000)

Lip's fast algorithm for discrete core-periphery bipartitioning.

For a binary, undirected network, this implements Lip's exact algorithm. Nodes are ordered by decreasing degree, and the loss (missing core-core edges plus observed periphery-periphery edges) is evaluated for every proper, nonempty degree-prefix core. The smallest core is returned when several sizes attain the same minimum.

Arguments

  • A: Adjacency matrix
  • max_iter: Deprecated compatibility keyword; ignored because the algorithm is exact. Passing it emits a deprecation warning (shown with --depwarn=yes).

Returns

  • CPResult with binary partition

Reference

Lip, S.Z.W. (2011). A Fast Algorithm for the Discrete Core/Periphery Bipartitioning Problem.

CorePeriphery.surprise_cp — Function
surprise_cp(A; max_iter=100)

Greedily maximize the exact bivariate-hypergeometric joint-tail surprise of de Jeude, Caldarelli and Squartini (2019, equation 4) for a simple, undirected binary graph. The returned quality is the negative log tail probability.

The tail is evaluated from the peak of the hypergeometric terms outwards and truncated once the geometrically bounded remainder is below double-precision resolution, so every candidate flip costs roughly the width of the hypergeometric peaks rather than the full O(m²) double sum. The optimizer is single-start greedy node flipping from a mean-degree split.

CorePeriphery.label_switching_cp — Function
label_switching_cp(A; max_iter=100, rng=Random.default_rng(), n_runs=1,
                   directed=false, cp_block=:ones)

Label-switching algorithm for core-periphery detection.

Uses greedy optimization of the discrete Pearson core quality with random processing orders and optional random restarts. It optimises the same objective as borgatti_everett_discrete and is the stronger optimiser of the two: the random sweep order and restarts escape more local optima.

Arguments

  • A: Adjacency matrix
  • max_iter: Maximum iterations
  • rng: Random number generator used for node ordering and random restarts
  • n_runs: Number of starts (the first is degree-based)
  • directed: With false (default) A must be symmetric and the correlation runs over the strict upper triangle. With true, asymmetric input is accepted and the correlation runs over all off-diagonal ordered dyads; symmetric input gives the same fit either way.
  • cp_block: :ones (default, Borgatti-Everett eq. 2) or :missing (Borgatti-Everett eq. 4, core-periphery dyads excluded from the correlation); see borgatti_everett_discrete and ideal_cp_matrix.

Isolates (nodes with zero strength) always receive coreness 0 and are never in core_nodes. A warning is emitted (once per session) when A has more than one connected component with at least two nodes.

Returns

  • CPResult with binary coreness

Reference

Yanchenko, K., Sengupta, S. (2025). A fast label-switching algorithm for core-periphery detection.

Multi-Pair Methods

CorePeriphery.multiple_cp_pairs — Function
multiple_cp_pairs(A; null_model=:er, max_pairs=10, min_pair_size=2,
                  max_iter=100, n_runs=10, pair_selection=:penalized,
                  pair_penalty=0.5, rng=Random.default_rng())

Detect multiple core-periphery pairs (Kojaku & Masuda 2017, 2018) by jointly switching each node's pair and binary core/periphery role.

Keyword arguments

  • null_model: :er (default) uses the Erdős–Rényi null of Kojaku & Masuda (2017) eq. (3), p = m / binom(n, 2); :configuration uses the degree-preserving null of Kojaku & Masuda (2018) eq. (13), P[i,j] = d[i] d[j] / (2m), implemented exactly (including the paper's i = j null term). Kojaku & Masuda (2018) recommend the configuration null: under the ER null any network with a heterogeneous degree distribution exhibits core-periphery pairs, because high-degree nodes are "core" relative to a uniform density even when the structure is fully explained by the degrees; the configuration null only rewards core-periphery structure beyond what the degree sequence implies. :er remains the default for continuity with 0.1 and with the 2017 paper, so pass null_model=:configuration (or use multiple_cp_pairs_config) for substantive analyses.
  • max_pairs: Largest number of pairs considered; any value from 1 to n is accepted (the effective cap is n ÷ min_pair_size).
  • min_pair_size: Smallest pair allowed.
  • max_iter, n_runs: Sweeps per run and number of random restarts; restarts cycle through 1:max_pairs initial pair counts.
  • pair_selection: Rule choosing the number of pairs among the best k-pair solutions found. :penalized (default) maximises the objective minus pair_penalty * (k - 1) * log(n) / n; :objective maximises the raw objective, which is nondecreasing in k in practice and therefore tends to over-partition (and to vary with the seed) on a single planted pair.
  • pair_penalty: Penalty strength for :penalized.
  • rng: Random-number generator.

Isolates (nodes with zero strength) are removed before fitting and reported with pair label 0 and coreness 0; n_pairs counts the pairs of the non-isolated nodes, whose labels are 1:n_pairs. The null densities are those of the non-isolated subnetwork. A warning is emitted (once per session) when A has more than one connected component with at least two nodes.

CorePeriphery.adjacency_to_matrix — Function
adjacency_to_matrix(edges, n; directed=false, combine=nothing)
adjacency_to_matrix(edges; directed=false, combine=nothing, sort_labels=false)

Convert an edge list to a dense Matrix{Float64} adjacency matrix.

Each edge is a tuple (i, j) (weight 1) or (i, j, weight). Self-loops, negative weights, and non-finite weights are rejected.

  • With n given, endpoints must be one-based integers in 1:n and the matrix is returned.
  • Without n, endpoints may be any node identifiers (strings, symbols, integers, ...). The method returns (A, labels), where labels[k] is the identifier of node k. Labels are listed in order of first appearance in edges (first endpoint before second), or sorted with sort_labels=true.

directed=false (default) stores every edge in both A[i, j] and A[j, i]; (i, j) and (j, i) then denote the same dyad. directed=true stores only A[i, j], so (i, j) and (j, i) are distinct dyads.

A dyad that occurs more than once with the same weight is stored once. A dyad that occurs with conflicting weights raises an ArgumentError unless combine names how to resolve it: :sum, :max, :min, or :last (the last supplied weight wins). With combine=:sum, repeated identical weights are summed as well.

block_densities(A, core_nodes)

Observed densities of the four blocks of the adjacency matrix induced by a core/periphery partition: the standard reporting companion of a Borgatti-Everett fit (UCINET's density table). Returns a NamedTuple (core_core, core_periphery, periphery_core, periphery_periphery) whose entries are the mean off-diagonal value of each block (the density for binary input, the mean weight for weighted input). A block with no dyads has density NaN.

core_periphery averages A[i, j] over core i and periphery j, and periphery_core over periphery i and core j; the two coincide for symmetric A. result may be any result with core_nodes and periphery_nodes fields (CPResult, CPDirectedResult).

CorePeriphery.ideal_cp_matrix — Function
ideal_cp_matrix(c; discrete=false, cp_block=:ones)

Generate the ideal core-periphery pattern matrix for a given coreness vector.

  • Continuous model (discrete=false): Δ[i,j] = c[i] * c[j].
  • Discrete model, cp_block=:ones: Δ[i,j] = max(c[i], c[j]), Borgatti and Everett (2000) eq. (2): core-periphery dyads are expected to be present.
  • Discrete model, cp_block=:missing: Borgatti and Everett (2000) eq. (4), the model they recommend. Δ[i,j] = 1 for core-core dyads, 0 for periphery-periphery dyads, and missing for core-periphery dyads, which are excluded from the correlation. Requires a binary c; the result is then a Matrix{Union{Missing,Float64}}.

The diagonal is always 0.

Arguments

  • c: Coreness vector (any real element type, values in [0,1])
  • discrete::Bool: If true, use the discrete ideal pattern
  • cp_block::Symbol: :ones or :missing (discrete model only)

Returns

  • Ideal core-periphery matrix (Matrix{Float64}, or Matrix{Union{Missing,Float64}} for cp_block=:missing)

core_quality(A, c; discrete=false, directed=false, cp_block=:ones)

Compute the Pearson correlation between adjacency values and the ideal core-periphery pattern (see ideal_cp_matrix) without materializing dyad vectors. Undirected inputs use the strict upper triangle; directed=true uses all ordered off-diagonal dyads. CorePeriphery.cp_significance — Function
cp_significance(A, detector; null_model=:configuration, n_samples=999,
                alpha=0.05, rng=Random.default_rng(),
                detector_kwargs=NamedTuple(), pass_rng=true, n_swaps=nothing,
                max_swap_attempts=nothing, swap_shortfall=:error,
                threaded=false, thread_schedule=:auto)

Test whether a detector's observed quality exceeds qualities obtained from random graphs. detector must return a result with a finite quality field. The :configuration null uses undirected degree-preserving double-edge swaps; :directed_configuration preserves binary in- and out-degrees through directed arc switches; :weight_permutation preserves topology and the edge-weight multiset; and :er samples an undirected Erdős-Rényi graph with observed density.

The returned CPSignificanceResult carries the plus-one Monte Carlo pvalue together with effect sizes: null_mean, null_std (sample standard deviation, NaN for a single sample), and zscore, the observed quality minus the null mean in null standard deviations (NaN when the null distribution is degenerate).

Null samples are drawn in the storage format of A: a SparseMatrixCSC input is sampled directly into compressed sparse column form, so detectors use their sparse kernels and memory stays O(workers · (n + m)) instead of O(workers · n²). Dense and sparse inputs of the same network give identical results for the same rng.

Configuration samples must complete all requested swaps by default; a shortfall raises ConvergenceError. Use max_swap_attempts to set the proposal budget and swap_shortfall=:warn or :accept to retain incomplete samples explicitly. Per-sample accepted swaps and attempt counts are returned in null_diagnostics (a NullDiagnostics).

With pass_rng=true (the default) a fresh child RNG, derived from rng, is passed as the rng keyword to every detector call whose method accepts one, so stochastic detectors produce reproducible null distributions. Detectors without an rng keyword are called without it; for detectors defined outside CorePeriphery a warning is emitted once, because their null distribution is then not reproducible from rng. Pass pass_rng=false to never forward it.

With threaded=true, null samples are distributed over Julia threads. Sample seeds are generated serially before execution and every worker owns its sampling workspace, so serial and threaded runs are bit-for-bit identical for deterministic detectors and for stochastic detectors receiving rng. Detectors must be thread-safe. thread_schedule=:auto (and :greedy) uses a work queue with one task per thread, which balances irregular detector runtimes; :static assigns samples round-robin to one task per thread and cannot be used from inside another threaded region.
